# 中文知识库系统开发任务清单

> **版本**：v1.0
> **日期**：2026-04-30
> **适用范围**：仅覆盖 Markdown 已准备完成后的功能搭建
> **前提说明**：PDF 已由第三方工具转换为 Markdown，本任务清单不包含 PDF 解析、OCR、版面恢复相关工作。

---

## 一、任务目标

当前阶段只建设以下主链路：

- Markdown 文档入库
- 元数据抽取与规范化
- 全文索引与向量索引
- 混合检索与结果重排
- claim 拆分与 AI 质检
- 规则校验
- 人工审核与审核记录
- 基础评测与回归测试

当前阶段明确不做：

- PDF 处理
- 知识图谱构建
- 多模型投票常态化
- 默认整篇长上下文注入
- 对外开放 API 平台化能力

---

## 二、任务分期

### Phase 0：项目骨架与基础约束

#### T001 目录结构初始化

- 优先级：高
- 目标：建立后续开发所需的标准目录结构
- 产出：`src`、`tests`、`data`、`index`、`review`、`rules`、`templates`、`Docs`
- 验收标准：项目目录清晰可用，后续模块有固定落点

#### T002 配置体系初始化

- 优先级：高
- 目标：统一管理模型、数据库、索引、日志等配置
- 产出：`config` 目录及配置加载模块
- 验收标准：不同环境下可通过配置切换参数，不在代码中硬编码密钥

#### T003 异常处理与日志基础设施

- 优先级：高
- 目标：为所有 API、索引任务、质检任务提供统一异常处理
- 产出：日志封装、异常基类、错误响应结构
- 验收标准：所有核心流程失败时都有可读日志和结构化错误输出

#### T004 测试骨架初始化

- 优先级：高
- 目标：建立单元测试、集成测试、测试数据目录
- 产出：`tests` 目录、测试配置、基础示例测试
- 验收标准：测试命令可以运行，新增模块可以快速补测试

---

### Phase 1：Markdown 入库与元数据规范化

#### T101 Markdown 文档发现与注册

- 优先级：高
- 目标：扫描指定目录中的 Markdown 文档并登记入库
- 产出：文档注册服务
- 输入：现有 Markdown 文件
- 输出：文档基础记录写入 SQLite
- 验收标准：能够识别新增文档、重复文档、已更新文档

#### T102 文档主键与版本字段设计

- 优先级：高
- 目标：统一 `doc_id`、`edition`、`section_id`、`chunk_id` 等关键字段
- 产出：文档元数据模型
- 验收标准：所有后续索引与检索流程统一依赖该主键体系

#### T103 Markdown 元数据抽取器

- 优先级：高
- 目标：从 Markdown 中提取文献名、版本、章节、页码、段落位置等信息
- 产出：元数据抽取模块
- 验收标准：至少能稳定抽取文献标题、章节层级、段落位置、来源标识

#### T104 Markdown 清洗与标准化

- 优先级：高
- 目标：清理空白、统一标题层级、保留引用片段边界
- 产出：标准化后的中间文本
- 验收标准：清洗前后可追溯，不破坏原文语义，不丢失出处信息

#### T105 文档入库事务封装

- 优先级：高
- 目标：将文档注册、元数据写入、索引状态更新放入事务
- 产出：入库事务模块
- 验收标准：任一步失败时回滚，不产生脏数据

---

### Phase 2：分块、实体归一与索引构建

#### T201 Markdown 智能分块器

- 优先级：高
- 目标：按章节、条目、专题段落等语义边界分块
- 产出：分块模块
- 验收标准：不使用纯固定字数切块；每个 chunk 可追溯到源文档位置

#### T202 Chunk 元数据结构定义

- 优先级：高
- 目标：统一 chunk 的字段结构，支持检索和引用
- 产出：chunk 数据模型
- 验收标准：包含 `chunk_id`、`doc_id`、`section_id`、`page_no`、`source_span`、`content`

#### T203 术语归一词表设计

- 优先级：高
- 目标：建立标准术语、别名、繁简、异体字映射表
- 产出：`term_dictionary.json`、`aliases.json`、`variant_map.json`
- 验收标准：常见术语写法能映射到统一标准名

#### T204 实体识别与归一模块

- 优先级：中
- 目标：对 chunk 中的人名、地名、机构、作品名、领域术语等实体做初步识别与归一
- 产出：实体抽取模块
- 验收标准：输出标准实体列表，且保留原始文本命中位置

#### T205 SQLite FTS5 全文索引构建

- 优先级：高
- 目标：为 chunk 建立全文索引
- 产出：FTS5 建表、写入、更新逻辑
- 验收标准：支持关键词、短语、精确术语召回

#### T206 ChromaDB 向量索引构建

- 优先级：高
- 目标：为 chunk 建立向量索引
- 产出：embedding 生成与写入逻辑
- 验收标准：支持增量写入、更新、删除与重建

#### T207 索引状态管理

- 优先级：中
- 目标：记录每个文档当前的入库、分块、全文索引、向量索引状态
- 产出：索引任务状态表
- 验收标准：可以查询每份文档当前构建进度和失败原因

---

### Phase 3：检索链路搭建

#### T301 全文检索接口

- 优先级：高
- 目标：基于 FTS5 提供关键词和短语检索
- 产出：全文检索服务
- 验收标准：支持按文献、版本、章节过滤结果

#### T302 向量检索接口

- 优先级：高
- 目标：基于 ChromaDB 提供语义检索
- 产出：向量检索服务
- 验收标准：支持 Top-K 检索与基础过滤条件

#### T303 混合检索融合器

- 优先级：高
- 目标：合并全文检索和向量检索结果并去重
- 产出：融合检索模块
- 验收标准：输出统一候选结果集，结果中保留召回来源

#### T304 检索重排模块

- 优先级：中
- 目标：对混合候选结果做二次排序
- 产出：重排服务封装
- 验收标准：重排失败时可回退到原始融合结果

#### T305 检索结果引用结构

- 优先级：高
- 目标：统一前端和质检模块使用的证据引用结构
- 产出：引用数据模型
- 验收标准：每条结果都包含 `source_doc`、`source_span`、`chunk_id`、片段文本

#### T306 检索缓存机制

- 优先级：中
- 目标：缓存 embedding 和热点查询结果
- 产出：缓存封装模块
- 验收标准：重复请求命中缓存时响应时间明显下降

---

### Phase 4：AI 质检主链路

#### T401 claim 拆分模块

- 优先级：高
- 目标：将用户输入文本拆分为独立可核验的 claim
- 产出：claim 分析模块
- 验收标准：能区分事实陈述、引用性表述、观点性表述

#### T402 claim 实体提取模块

- 优先级：高
- 目标：从 claim 中提取术语、时间、数字、单位、领域实体等信息
- 产出：claim 实体分析模块
- 验收标准：提取结果支持规则引擎和检索模块复用

#### T403 质检请求编排器

- 优先级：高
- 目标：串联 claim 拆分、规则校验、检索、证据注入、LLM 判断
- 产出：质检主服务
- 验收标准：输入一段文本后，返回结构化 claim 结果数组

#### T404 证据注入策略实现

- 优先级：高
- 目标：按 `Top-N chunk + 邻接 chunk + 精确片段` 组织上下文
- 产出：上下文构建模块
- 验收标准：默认不注入整篇文档，且上下文长度受控

#### T405 结构化输出校验器

- 优先级：高
- 目标：约束 LLM 输出为固定 JSON 结构
- 产出：输出校验与重试模块
- 验收标准：JSON 解析失败时自动重试一次，仍失败则转人工审核

#### T406 质检结果持久化

- 优先级：中
- 目标：保存质检请求、claim 结果、证据引用、模型响应摘要
- 产出：质检记录表
- 验收标准：可以按时间、模板、文档来源查询历史记录

---

### Phase 5：规则引擎

#### T501 规则数据结构设计

- 优先级：高
- 目标：定义规则配置、规则数据、规则命中结果的数据结构
- 产出：规则模型与 YAML 规范
- 验收标准：规则定义和执行逻辑分离

#### T502 通用结构与引用规则

- 优先级：高
- 目标：实现引用完整性、标题层级、术语规范化等首批高确定性规则
- 产出：规则文件与校验逻辑
- 验收标准：命中时返回规则来源、严重级别和建议

#### T503 数字与单位归一规则

- 优先级：高
- 目标：处理数字格式、日期格式、计量单位等归一判断
- 产出：单位映射与规则模块
- 验收标准：相关判断前先完成单位归一

#### T504 可选领域规则包

- 优先级：中
- 目标：补充医学、法规或其他高风险领域的可选规则包
- 产出：领域规则文件
- 验收标准：可按场景开关启用，不影响通用主链路

#### T505 规则命中与质检编排集成

- 优先级：高
- 目标：让规则引擎输出可直接进入质检结果
- 产出：规则集成逻辑
- 验收标准：命中高风险规则时可直接标记 `contradicted` 或 `manual_review_required`

---

### Phase 6：审核台与管理功能

#### T601 文档检索界面

- 优先级：中
- 目标：支持关键词搜索、语义搜索、结果查看
- 产出：检索页面
- 验收标准：可查看结果片段、来源、定位信息

#### T602 AI 质检台界面

- 优先级：高
- 目标：支持输入文本、查看 claim 结果和证据
- 产出：质检页面
- 验收标准：可清晰展示 claim、verdict、confidence、evidence、source

#### T603 人工审核操作界面

- 优先级：高
- 目标：支持通过、驳回、修改、备注
- 产出：审核页面
- 验收标准：审核动作可持久化，可回看历史修改

#### T604 审核记录查询

- 优先级：中
- 目标：按日期、场景、结论、文档查询历史记录
- 产出：记录查询页面
- 验收标准：可快速定位过去的审核案例和证据来源

#### T605 文档入库状态页

- 优先级：中
- 目标：查看每份 Markdown 文档的入库状态、索引状态和失败原因
- 产出：状态页
- 验收标准：出现失败时可直观看到失败步骤

---

### Phase 7：评测与回归测试

#### T701 检索评测集整理

- 优先级：高
- 目标：准备问题、标准证据、目标文档范围
- 产出：检索评测数据集
- 验收标准：至少覆盖 50 条真实检索样本

#### T702 claim 质检评测集整理

- 优先级：高
- 目标：整理待核验陈述及人工标注结论
- 产出：claim 评测数据集
- 验收标准：至少覆盖 verified、contradicted、suspected 三类结论

#### T703 规则回归测试

- 优先级：高
- 目标：为每条规则准备命中与非命中样本
- 产出：规则测试用例
- 验收标准：调整规则后可快速判断误报和漏报

#### T704 检索评测脚本

- 优先级：中
- 目标：自动计算 Top-5、Top-10 命中率
- 产出：检索评测脚本
- 验收标准：执行后自动输出评测结果报表

#### T705 质检评测脚本

- 优先级：中
- 目标：统计 claim 判定准确率与证据可追溯率
- 产出：质检评测脚本
- 验收标准：可重复运行并输出稳定指标

#### T706 性能与成本统计

- 优先级：中
- 目标：统计接口耗时、模型调用次数、单次成本估算
- 产出：性能与成本报表
- 验收标准：可以按阶段评估是否需要继续扩容或降级

## 三、推荐执行顺序

建议按以下顺序推进：

1. `T001` - `T004`：先搭好骨架、配置、异常、测试
2. `T101` - `T105`：先让 Markdown 文档能够稳定注册入库
3. `T201` - `T207`：建立 chunk、实体归一、全文索引、向量索引
4. `T301` - `T305`：先打通检索链路，再补缓存
5. `T401` - `T405`：打通质检主链路
6. `T501` - `T505`：补通用规则与可选领域规则
7. `T602` - `T604`：优先做质检台和审核台，再补管理页
8. `T701` - `T706`：补评测与成本统计闭环
