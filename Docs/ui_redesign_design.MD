# UI 重构设计规范（dev）

> 版本：v2.0
> 日期：2026-05-08
> 适用分支：`dev`
> 说明：本文档是当前 UI 重构的强约束规范。后续页面调整必须先满足本文档，再做视觉润色。

---

## 一、目标

本轮 UI 重构只做三件事：

- 修正错误布局，不再让页面靠堆卡片制造层次
- 让模块结构符合实际操作路径，而不是机械套双栏
- 保留 `Gradio` 与现有业务逻辑，只重做前端结构与样式

明确不做：

- 不改事件链路
- 不改业务含义
- 不改数据库与服务层协议
- 不用“加更多边框”来掩盖结构问题

---

## 二、设计总原则

本项目沿用 `frontend-design` skill，但落地方式不是做花哨视觉，而是建立严格的信息编排和模块落位规则：

- 风格基调：冷静、专业、轻编辑化
- 页面目标：像工具工作台，不像营销页
- 核心判断标准：用户是否能顺着视线完成任务，而不是页面是否“看起来更满”

---

## 三、强约束规则

### 3.1 外框层级规则

- 一个语义模块只允许一个主外框
- 禁止“工作区外框 + 面板外框 + 内容外框”连续三层视觉包裹
- `Group`、`Row`、`Column` 可以存在结构嵌套，但不能全部带可见卡片样式
- 外层容器如果只是排版容器，必须是透明容器，不能再画边框和阴影

### 3.2 单栏与双栏规则

- 表格类模块默认单栏全宽显示
- 详情很长、表格很多、需要横向阅读的模块，一律优先单栏
- 只有以下两种情况允许双栏：
- 左右存在明确主从关系，例如“列表 / 当前详情”
- 两个模块高度接近、职责清晰且并排更利于比较
- 不能因为页面空着就强行双栏
- 禁止把长模块硬塞进窄列

### 3.3 按钮放置规则

- 按钮必须放在所属模块内部
- 按钮必须与它控制的结果区、列表区或表单区相邻
- 按钮与模块边框之间必须保留安全间距，不能贴边
- 不能把下载按钮悬空放在模块外侧或模块底边上
- 一个动作如果有结果反馈，按钮和反馈必须在同一个语义分区闭环
- 页级按钮优先靠近页级主结果；局部按钮优先靠近局部结果

### 3.4 结果区规则

- 结果区不是装饰卡片，是动作反馈区
- 结果区必须跟随对应动作区
- 下载结果、导出结果、保存结果、审核结果不能混在无关模块里
- 长链接、路径、报错文本必须支持折行

### 3.5 说明区规则

- 帮助说明优先写在模块头部或模块内部
- 说明区不能再单独套一层装饰卡片后放进另一个卡片里
- 说明只解释当前模块，不抢主流程

### 3.6 长模块规则

- 长模块必须拆成“详情 / 编辑 / 结果”三个层级，而不是一整条拉到底
- 详情面板和编辑面板可以双栏，但前提是它们属于同一主流程且宽度合理
- 过长表单需要分组，但分组内部优先用标题和间距，不再叠小卡片

---

## 四、页面骨架规范

### 4.1 顶部区域

- 放筛选、输入、当前上下文和必要说明
- 不放冗长结果
- 顶部区域允许双栏，但只能是“输入 / 辅助说明”或“主上下文 / 辅助概览”

### 4.2 主工作区

- 主工作区优先承载表格、列表、详情、编辑区
- 表格优先单栏全宽
- 主详情或编辑区仅在明确有对照价值时才与另一模块并排

### 4.3 底部辅助区

- 放导出、结果反馈、历史回看、次级能力
- 底部辅助区不能反过来抢主工作区位置

---

## 五、页面级规范

### 5.1 知识库检索

正确结构应为：

1. 检索输入区
2. 检索说明或摘要
3. 检索结果表格，全宽单栏
4. 当前结果详情
5. 下载动作与下载结果，同区闭环

禁止：

- 结果表格被压在窄列里
- 下载按钮单独漂浮在表格外侧
- 结果详情和导出动作互相抢位置

### 5.2 功能设置

正确结构应为：

1. 顶部说明与运行环境概览
2. 模板列表，全宽或宽列表优先
3. 模板详情与模板编辑，左右合理并排
4. 模板结果区
5. 知识库设置区按相同逻辑重排
6. 页面级导出动作放在页底独立模块

禁止：

- 模板详情做成长条模块
- 列表、详情、编辑全部挤在一个横排里
- 分组靠再套卡片来建立层级

### 5.3 AI 质检

- 主流程保持“输入 -> 摘要 -> Claim -> 证据 -> 历史”
- `效果评测` 属于次级能力，不抢主流程宽度
- 表格与列表优先放宽，不再机械平均双栏

### 5.4 人工审核

- 候选列表与证据列表优先保证宽度
- 详情与审核动作只在合理高度下并排
- 审核结果与导出结果必须贴近审核动作

### 5.5 知识库管理

- 当前文档和主要操作优先
- 文档列表与分页保持宽表格布局
- 入库质检中的抽样表、结果表同样优先单栏放宽

---

## 六、技术落地要求

- `pages.py` 负责结构重排与 `elem_id` 维护
- `UI_CSS` 负责把透明容器和语义模块区分开
- `viewmodels.py` 继续负责 HTML 内容格式化
- 结构变动后同步更新 `tests/unit/test_ui.py`
- 每次修改后执行诊断和 `UI` 测试

---

## 七、验收标准

- 页面不再出现三层及以上视觉卡片嵌套
- 表格模块默认全宽单栏
- 长模块不再被压成窄列
- 所有按钮都在所属模块内部，且与边框保留安全间距
- 动作与结果闭环清晰
- `dev` 分支全程可验证
