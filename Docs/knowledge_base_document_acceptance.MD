# 知识库与文档关系修复验收清单

## 程序说明

- 本文用于验收“知识库目录与文档归属统一规则”修复结果。
- 当前规则：所有知识库包括 `default`，都只识别各自 `Input/<knowledge_base_id>` 子目录中的文件。
- 历史根目录文件 `a1.md`、`a2.md` 已迁移到 `Input/default`。

## 预期规则

- 新建知识库后，自动创建 `Input/<knowledge_base_id>` 目录。
- `default` 只识别 `Input/default`。
- 非默认知识库只识别各自目录，不扫描其他知识库目录，也不扫描 `Input` 根目录。
- 批量注册只处理当前知识库目录里的文档。
- 调整文档归属后，磁盘文件位置与数据库归属保持一致。

## 验收步骤

### 1. 新建知识库目录初始化

- 打开“功能设置” -> “配置管理” -> “知识库管理”。
- 新建一个知识库，例如：`kb_acceptance_docs`。
- 预期结果：磁盘上立即出现 `Input/kb_acceptance_docs` 目录。
- 预期结果：知识库管理页列表出现该知识库。
- 预期结果：知识库管理页、知识库检索、AI质检、人工审核的知识库下拉都能看到该知识库。

### 2. 默认知识库目录隔离

- 确认 `Input/default` 下存在 `a1.md`、`a2.md`。
- 确认 `Input` 根目录下不再保留 `a1.md`、`a2.md`。
- 切换到“知识库管理”页的默认知识库。
- 点击“刷新文档列表”或等价刷新动作。
- 预期结果：文档列表中能看到 `a1.md`、`a2.md`。
- 预期结果：默认知识库下不应出现其他知识库目录中的文档。

### 3. 非默认知识库目录隔离

- 在 `Input/kb_acceptance_docs` 下放入一个测试 Markdown 文件，例如 `case_kb_only.md`。
- 切换“知识库管理”页到 `kb_acceptance_docs`。
- 点击刷新。
- 预期结果：列表中出现 `case_kb_only.md`。
- 预期结果：列表中不出现 `a1.md`、`a2.md`。
- 切回默认知识库。
- 预期结果：默认知识库列表中不出现 `case_kb_only.md`。

### 4. 批量注册只处理当前知识库目录

- 在默认知识库与 `kb_acceptance_docs` 各准备至少一个未入库 Markdown 文件。
- 切换到默认知识库，执行“注册全部待处理”。
- 预期结果：只注册默认知识库目录中的文档。
- 预期结果：`kb_acceptance_docs` 目录中的文档状态不应被改变。
- 再切换到 `kb_acceptance_docs`，执行“注册全部待处理”。
- 预期结果：只注册 `kb_acceptance_docs` 当前目录中的文档。

### 5. 单文档注册与状态刷新

- 在当前知识库选择一个未入库文档。
- 点击“注册当前文档”。
- 预期结果：结果区显示成功。
- 预期结果：文档状态变为已注册/已索引的对应状态。
- 点击“刷新入库状态”。
- 预期结果：状态与数据库统计保持一致。

### 6. 调整文档归属

- 先确保当前知识库中至少有一篇已入库文档。
- 在“目标知识库”选择另一个知识库，例如从 `default` 调整到 `kb_acceptance_docs`。
- 点击“调整归属”。
- 预期结果：结果区显示目标知识库与新路径。
- 预期结果：源知识库文档列表中不再出现该文档。
- 预期结果：切换到目标知识库后，可以看到该文档。
- 预期结果：磁盘文件已移动到 `Input/<目标知识库ID>/`。

### 7. 未入库文档重建保护

- 选择一个尚未入库的文档。
- 点击“重建当前文档”。
- 预期结果：结果区提示“当前文档尚未入库，无法重建”。
- 预期结果：不会误创建索引记录。

### 8. 已入库文档重建

- 选择一个已完成注册的文档。
- 点击“重建当前文档”。
- 预期结果：结果区显示重建已接受或成功。
- 预期结果：刷新后文档仍留在当前知识库，状态不异常。

### 9. 分页与切换稳定性

- 在单个知识库下准备超过 10 个文档。
- 检查数据库统计表和文档列表分页。
- 来回切换知识库并翻页。
- 预期结果：分页信息正确。
- 预期结果：切换知识库后不串页、不串库、不残留上一知识库的数据。
