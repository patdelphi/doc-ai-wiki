# 中文知识库系统 MVP 验收清单

> **版本**：v1.0
> **日期**：2026-04-30
> **说明**：本文档用于约束 MVP 开发阶段的最小交付范围，避免开发范围漂移。

---

## 一、验收目标

MVP 阶段必须完成以下 4 项核心能力：

- Markdown 文档可稳定入库
- 全文检索与向量检索可用
- 输入文本可输出结构化 claim 质检结果
- 人工审核结果可持久化查询

不属于本次验收范围：

- 知识图谱
- 批量质检
- 默认整篇长上下文注入
- 多模型投票常态化
- 对外开放 API 平台化能力
- 高风险专业推荐能力

## 五、必交付接口

### 5.1 文档入库

- `POST /ingest/register`
- `POST /ingest/rebuild`
- `GET /ingest/status`

### 5.2 检索

- `GET /search/fulltext`
- `GET /search/vector`
- `GET /search/hybrid`

### 5.3 质检

- `POST /quality/check`
- `GET /quality/result/{check_id}`

### 5.4 审核

- `POST /review/submit`
- `GET /review/list`

验收要求：

- 接口能正常返回 JSON
- 错误时返回统一错误结构
- 写接口具备异常处理
- 高风险结论必须返回证据来源

## 六、页面最小要求

必须支持：

- 查看文档入库状态
- 查看索引状态
- 查看失败原因

### 6.2 文档检索页

必须支持：

- 输入关键词或自然语言查询
- 展示检索结果片段
- 展示来源文档与位置

### 6.3 AI 质检台

必须支持：

- 输入待质检文本
- 展示 claim 拆分结果
- 展示 verdict、confidence、evidence、source

### 6.4 审核页

必须支持：

- 对单条 claim 执行通过、驳回、修改
- 保存审核备注
- 查看审核后的结论

## 九、功能验收清单

### 8.1 文档入库

- [ ] 能注册 1 份 Markdown 文档
- [ ] 能识别重复文档
- [ ] 能识别已更新文档
- [ ] 元数据可成功写入 SQLite
- [ ] 分块可成功生成并入库
- [ ] FTS5 索引可成功构建
- [ ] 向量索引可成功构建

### 8.2 检索能力

- [ ] 全文检索可返回结果
- [ ] 向量检索可返回结果
- [ ] 混合检索可合并结果并去重
- [ ] 检索结果包含 `chunk_id`
- [ ] 检索结果包含 `source_doc` 或等价文档标识
- [ ] 检索结果包含 `source_span`

### 8.3 质检能力

- [ ] 输入文本后可拆分 claim
- [ ] 每条 claim 可返回 verdict
- [ ] 每条 claim 可返回 confidence
- [ ] 每条 claim 可返回 evidence
- [ ] 无证据时不会输出 `verified`
- [ ] 低置信度结果会标记人工复核

### 8.4 审核能力

- [ ] 审核动作可写入数据库
- [ ] 原始 verdict 不被覆盖
- [ ] 审核后 verdict 可查询
- [ ] 审核备注可保存

## 十、质量指标

MVP 验收建议以以下指标为参考：

| 维度 | 指标 | 目标 |
|------|------|------|
| 检索 | Top-5 命中率 | >= 80% |
| 检索 | Top-10 命中率 | >= 90% |
| 质检 | claim 判定准确率 | >= 80% |
| 质检 | 证据可追溯率 | >= 95% |
| 规则 | 误报率 | <= 5% |
| 规则 | 漏报率 | <= 5% |
| 性能 | 单次质检平均耗时 | <= 15 秒 |

---

## 十一、验收结论标准

满足以下条件即可判定通过 MVP 验收：

- 必交付文档齐全
- 必交付接口可用
- 必交付页面可用
- 必交付测试通过
- 关键质量指标达到目标或接近目标
- 未出现阻断开发或阻断使用的核心缺陷
