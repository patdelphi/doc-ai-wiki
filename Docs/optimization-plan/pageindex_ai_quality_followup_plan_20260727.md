# PageIndex 与 AI 质检质量收口优化计划

## 目标

- PageIndex 回答不仅格式可读，还必须具备结论、证据边界、来源和不确定点。
- AI 质检稳定区分危险错误断言、安全边界、证据缺口和复杂复合 Claim。
- LLM 失败或降级必须有明确终态、原因和可追踪记录，不能让前端一直显示运行中。
- 使用真实问题验证回答内容，并将 PageIndex 与 AI 质检测试结果全部写入现有数据库。

## 执行范围

- `src/pageindex/answer_orchestrator.py`
- `src/pageindex/service.py`
- `src/quality/service.py`
- `src/ai/llm.py`
- 必要的 UI 终态展示代码
- 对应单元测试、真实评测记录和结果文档

不进行数据库结构迁移、不安装新依赖、不删除现有文件、不修改无关页面，也不自动 commit 或 push。

## 完成标准

1. PageIndex 结构化答案不出现 Python dict repr。
2. 严谨问答、证据审查和医学安全模板的回答必须包含结论、证据边界、来源、不确定点；缺失时自动保守修复或明确降级。
3. 每条来源至少能追溯到文档、chunk 或原文位置之一。
4. 危险错误断言测试全部为 `rejected/high`。
5. “不能替代、不能随意、不是唯一”等安全边界不得被误判为直接反证。
6. “没有证据、尚未证实”等证据缺口不得判为 `verified`，保持 `needs_review/insufficient`。
7. 多句、多对象、时间、人群、剂量、比较和否定嵌套 Claim 能正确拆分并给出可解释理由。
8. LLM 调用失败时，前端必须收到失败或降级终态；历史记录中可看到失败阶段和原因。
9. 新增真实 PageIndex 与 AI 质检结果全部落入 `index/app.db`，并回读核验 ID、结论和 Claim 数量。
10. 聚焦测试、Ruff、受影响模块 Mypy 和完整 Pytest 通过；若存在历史失败，单独列明且不得掩盖。
