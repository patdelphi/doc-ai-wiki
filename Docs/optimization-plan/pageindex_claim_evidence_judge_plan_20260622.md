# PageIndex Claim-Evidence Judge 优化计划

## 目标

把 PageIndex 回答从“相关证据摘要”升级为通用的“命题-证据审查”流程。

核心原则：先判断证据是否支持用户问句本身，再生成结论。不能把背景、案例、组合方案、方法语境、风险条件当成直接支持。

## 适用范围

该能力不限定医学问题，适用于：

- 学术论文问答
- 法规与制度问答
- 工艺与产品说明问答
- 历史、人物、观点类问答
- 医学、养生、用药类问答

## 通用流程

1. 将用户问题规范化为待验证命题。
2. 对每条证据判断它与命题的关系。
3. 按证据关系生成结论。
4. 模板只负责表达，不负责自由判断证据是否支持命题。

## 证据关系类型

- `direct_support`：证据直接支持用户命题。
- `direct_refute`：证据直接反驳用户命题。
- `partial_support`：证据只支持命题的一部分。
- `context_only`：证据只是背景或相关语境。
- `example_only`：证据只是案例，不能泛化为命题成立。
- `method_or_formula_context`：证据只出现在组合方案、方法、配方、流程或系统语境中，不能证明单项命题成立。
- `risk_or_condition`：证据包含条件、限制、风险、例外或前提。
- `insufficient`：证据不足以判断。

## 结论策略

- 存在 `direct_refute`：结论必须说明当前证据不支持或反驳该命题。
- 存在 `direct_support`：结论可以说明当前证据支持该命题，同时保留适用边界。
- 只有 `partial_support`：结论必须说明只能支持部分内容，不能推出完整命题。
- 只有 `method_or_formula_context`：结论必须说明不能证明用户问的单项命题。
- 只有 `example_only`：结论必须说明只是个例或样例，不能泛化。
- 只有 `context_only` / `risk_or_condition` / `insufficient`：结论必须说明证据不足，不能得出结论。

## P0 实施范围

1. 新增通用 Evidence Judge 模块，集中管理证据关系类型和结论策略。
2. PageIndex 本地降级答案统一走 Evidence Judge，不再在回答函数里写领域补丁。
3. 保留现有字段 `evidence_type` / `evidence_label`，但值升级为通用关系类型。
4. 补充跨领域单测：法规、工艺、人物观点、案例泛化、组合方案语境。
5. 修正现有“方剂语境”逻辑为通用 `method_or_formula_context`，不写成医学专用规则。

## P1 实施范围

1. LLM 可用时要求输出结构化 `claim`、`evidence_relations`、`conclusion_policy`。
2. PageIndex 模板增加通用证据关系变量说明。
3. 最终答案由程序校验结构化关系后生成或兜底修正，减少 LLM 自由发挥。

## 验收标准

- “吃阿胶能缓解痛经”不能因方剂语境输出肯定或模糊结论。
- “某法规允许某行为”只有背景条款时不能输出允许。
- “某工艺能提高产量”只有案例或流程描述时不能泛化为一定提高。
- “某人物提出某观点”只有相关人物背景时不能输出提出过。
- PageIndex 聚焦测试和全量测试通过。
