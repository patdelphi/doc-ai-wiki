# PageIndex 论文合集文章边界识别计划

> 时间：2026-06-23
> 范围：`src/pageindex/service.py`、`src/chunking`、`tests/unit/test_pageindex_service.py`、`tests/evaluation/pageindex_cases.jsonl`
> 目标：减少论文合集类 Markdown 在一个超大 PageIndex 树中混杂多篇文章主题，提升 PageIndex 候选节点召回与答案证据边界的稳定性。

## 背景

当前 PageIndex 构建前会生成 `source.cleaned.md`，已清理图片占位、目录标题和分隔线噪音，但仍把论文合集类 Markdown 作为一个整体交给 PageIndex 建树。

这会带来三个问题：

- 多篇论文标题、作者、摘要、正文在同一棵树中混杂，候选节点容易跨文章漂移。
- 用户问某个具体方法、疗效或检测项时，LLM 可能选到相邻论文或目录式节点。
- RAG/FTS 补证据可以命中具体 chunk，但 PageIndex 主节点无法稳定表达“属于哪篇文章”。

## 设计原则

- 不替换 vendor PageIndex，不自造完整语义树。
- 不修改用户原始 Markdown，只影响 PageIndex workspace 中的清洗副本。
- 文章边界识别先作为构建前预处理增强，不改数据库结构。
- 边界识别必须保守：宁可少拆，不要误拆普通章节。
- 论文合集识别失败时回退当前清洗结果，不阻断构建。

## 边界识别目标

在 `source.cleaned.md` 中为疑似论文边界补充稳定的上层标题或锚点，让 PageIndex 更容易形成“文章 -> 章节 -> 段落”的树。

推荐输出形态：

```markdown
# 论文 001：阿胶治疗肿瘤相关性贫血的效果及安全性

原始标题、作者、期刊信息、摘要、正文...

# 论文 002：阿胶珠结合黄体酮用于妊娠早期...

原始标题、作者、期刊信息、摘要、正文...
```

## 候选边界特征

第一阶段只用可解释规则识别高置信边界：

- 目录项/题录模式：标题后跟作者、机构、期刊、年份卷期页码。
- 标题模式：连续短行中出现论文题名，下一行或附近出现作者/期刊。
- 摘要模式：标题后 20 行内出现 `摘要`、`关键词`、`Abstract`、`Keywords`。
- 编号模式：`1.....标题....页码` 这类合集目录可作为弱信号，但不能单独拆正文。

明确不作为边界：

- 普通章节标题，如 `功效`、`应用`、`药理`。
- 表题、图题、参考文献条目。
- 方剂名、药材名、短小小节标题。

## 分阶段实施

### P0：只做检测与诊断

- 新增 `detect_article_boundaries(markdown_text)`，返回候选边界、标题、置信理由。
- PageIndex 构建 debug 或日志中记录检测到的边界数量。
- 不改变 `source.cleaned.md` 输出。
- 用真实论文合集片段补单测，验证不会误识别普通章节。

### P1：生成增强清洗副本

- 新增 `_enhance_article_boundaries_for_pageindex()`，仅在高置信边界数量大于等于 2 时启用。
- 在边界前插入规范化一级标题，保留原文标题和正文。
- 写入 `source.cleaned.md`，不改变原始文档。
- 单测覆盖：多篇论文能插入 `# 论文 001...`，普通文档不插入。

### P2：检索与展示联动

- PageIndex 候选节点 debug 显示文章标题上下文。
- RAG/FTS 证据的 `heading_path` 与 PageIndex 节点标题互相补充。
- 历史和导出中保留文章级上下文，便于用户判断证据来自哪篇论文。

## 验收标准

- 论文合集类 Markdown 构建后，PageIndex 树候选能优先显示文章级标题。
- 普通单文档、通典类章节文档不会被错误插入论文标题。
- “阿胶有哪些质量检测方法”等信息抽取问题，证据来源能区分不同论文或章节。
- PageIndex 主证据和 RAG/FTS 证据仍能稳定合并，不因文章边界增强丢失引用。
- 单测不调用外部 API。

## 暂不做

- 不拆成多个数据库文档。
- 不改变 `documents.doc_uid` 或 `pageindex_indexes` 结构。
- 不引入新外部解析库。
- 不把低置信目录页直接当正文文章边界。
