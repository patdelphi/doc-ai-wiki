# 代码审查执行清单

## 说明
- 本文档按文件分组整理整改项，便于逐文件推进。
- 基于 "Docs/code_review_checklist.MD" 进一步细化。
- 优先级分为：P0、P1、P2。

## "src/app.py"
- 优先级：P0
- [ ] 为写接口补认证与鉴权：入库、重建、质检、知识库新增、知识库删除、审核提交。
- [ ] 明确读接口访问策略：健康检查是否匿名开放、检索接口是否要求登录。
- [ ] 统一接口权限校验入口，避免每个路由重复散落判断。
- [ ] 为 API 权限边界补测试：未登录、普通用户、管理员三类场景。
- 验收标准：未授权用户无法访问受保护接口；管理员与普通用户权限边界清晰。

## "src/auth/service.py"
- 优先级：P0
- [ ] 移除或重构默认 "admin/admin" 自动创建逻辑，避免弱口令。
- [ ] 在 "authenticate()" 中补充 "is_active" 校验，禁用用户不可登录。
- [ ] 统一密码哈希方案，避免新旧逻辑长期并存。
- [ ] 为登录、注册、改密、禁用用户、权限更新补最小单测。
- [ ] 明确初始化职责边界，避免认证数据由多个层重复补齐。
- 验收标准：不存在默认弱口令；禁用用户登录失败；认证流程均有测试覆盖。

## "src/ui/pages.py"
- 优先级：P0 / P2
- [ ] 让登录态中的 "tab_names" 真正控制主 Tabs 的可见范围。
- [ ] 让登录态中的 "kb_ids" 真正限制知识库选择范围。
- [ ] 复核首屏显示逻辑，避免页面可见性过度依赖 BrowserState 恢复事件。
- [ ] 按页面布局、事件绑定、权限控制拆分大文件，降低单文件复杂度。
- [ ] 为 UI 权限显示补测试：不同用户仅能看到授权 Tab 与知识库。
- 验收标准：普通用户只看到授权范围；刷新页面后显示与权限状态稳定一致。

## "src/ui/app.py"
- 优先级：P1
- [ ] 评估长生命周期 SQLite 连接的并发风险。
- [ ] 明确连接关闭时机，避免资源长期占用。
- [ ] 复核 "check_same_thread=False" 的使用边界，确认是否有更稳妥的连接管理方式。
- 验收标准：UI 启动与交互过程无明显连接泄漏或并发异常。

## "src/db/schema.py"
- 优先级：P1
- [ ] 为 "review_records.claim_id" 增加外键或等效一致性约束。
- [ ] 复核审核、质检、知识库三者之间的删除级联关系。
- [ ] 明确孤儿记录的治理策略：禁止、级联删除或软删除。
- 验收标准：删除上游数据后，不会留下无法解释的审核孤儿数据。

## "src/db/repositories.py"
- 优先级：P1 / P2
- [ ] 补充知识库删除前的关联数据检查，避免只检查文档数量。
- [ ] 明确删除失败时返回的业务错误，而不是仅依赖数据库异常。
- [ ] 评估按领域拆分仓储：知识库、文档、质检、审核分别管理。
- 验收标准：删除知识库时错误信息明确；仓储职责边界更清晰。

## "src/knowledge_base/service.py"
- 优先级：P1
- [ ] 删除知识库前增加对 "quality_checks"、审核记录等关联数据的前置校验。
- [ ] 明确默认知识库、空知识库、有历史记录知识库三类删除策略。
- [ ] 为删除场景补回归测试。
- 验收标准：知识库删除逻辑与数据库约束一致，用户侧错误提示清晰。

## "src/retrieval/vector_store.py"
- 优先级：P1
- [ ] 配合启动入口调整初始化顺序，避免数据库未完成初始化时触发向量修复逻辑。
- [ ] 补覆盖 "count_by_doc_uid()" 与真实 collection.get 调用方式的测试。
- [ ] 复核自动修复逻辑在旧库、空库、残留索引场景下的副作用。
- 验收标准：启动路径稳定；旧索引修复与空库启动可预测。

## "tests/unit/test_startup_scripts.py"
- 优先级：P0
- [ ] 更新脚本名断言，使之与当前实际脚本一致。
- [ ] 若保留旧入口，则明确测试旧入口的转发关系；若不保留，则删除过期用例。
- 验收标准：测试目标与仓库真实脚本结构一致。

## "tests/integration/test_app.py"
- 优先级：P0
- [ ] 修复启动脚本相关断言，避免继续引用不存在的旧脚本文件。
- [ ] 复核集成测试是否覆盖新的脚本入口和 UI 启动路径。
- 验收标准：脚本相关集成测试能稳定通过，并反映当前真实入口。

## "Docs/migrations/_apply_auth.py"
- 优先级：P2
- [ ] 判断是否仍有保留价值；若仅是一次性脚本，应标记废弃或移出正式文档区。
- [ ] 避免后续开发误将其视为正式迁移方案。
- 验收标准：文档目录中不再混入容易误导的历史脚本资产。

## "Docs/migrations/_apply_auth_v2.py"
- 优先级：P2
- [ ] 与上一版脚本一起做去重与归档决策。
- [ ] 若保留，需明确用途、适用范围与已失效说明。
- 验收标准：历史脚本状态清晰，团队不会误用。

## 建议执行批次
1. 第一批："src/app.py"、"src/auth/service.py"、"src/ui/pages.py"、相关权限测试。
2. 第二批："tests/unit/test_startup_scripts.py"、"tests/integration/test_app.py"、启动路径相关修正。
3. 第三批："src/db/schema.py"、"src/db/repositories.py"、"src/knowledge_base/service.py"、相关删除与一致性测试。
4. 第四批："src/ui/app.py"、"src/retrieval/vector_store.py"、启动与连接管理优化。
5. 第五批："src/ui/pages.py"、"src/db/repositories.py"、"Docs/migrations" 结构收敛。

## 每批完成后的最小验证
- [ ] 运行 "lint"。
- [ ] 运行受影响范围的 "test"。
- [ ] 如涉及接口或模型结构，补充必要的 "type-check" 或 "build"。
- [ ] 复核文档、脚本名、测试断言三者一致。
